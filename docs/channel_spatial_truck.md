# 完整前缀信道解码器：局部空间去噪对照

本实验不替换现有基线。加载已完成的
`truck_full_prefix_gpu3_20261015_094337/full_prefix10/checkpoints/final/codec.pt`，
从其 6000 步权重出发。8/24/48 个复符号、48 维 y、可靠 16bit XYZ、语义教师和
纯 y MSE 目标不变。固定 10 dB AWGN，不做渲染更新。

## 两个同源组

- `pointwise10`：每个点只读取自身；新增残差网络增加容量但不跨点混合。
- `spatial10`：相同参数结构和初始化，在当前局部块内用可靠 XYZ 寻找最多 16 个
  最近邻（包含自身），学习注意力聚合，再预测逐点残差。默认隐藏宽度 64。

两组均冻结原完整前缀编解码器、语义模块和属性归一化参数，只训练新增残差支路。
源 Adam 不用于这些新参数；新支路使用新的 Adam，默认学习率继承源信道解码器的
1e-4。`--lr` 可显式覆盖。这里的 2000 步是每组新增真实 optimizer 更新次数，
源总步数 6000 → 日志总步数 8000；并未减少更新次数或使用梯度累计。

训练批次、q1/q2/q3/mixed 顺序、噪声流配对；新增网络非零隐藏权重也逐参数相同。
最终读出初始化为零，保证两组初始输出与源模型一致。逐点自身路径从不被替换。
零输出层从第一步可获得梯度，其他新层在输出层开始变化后参与学习。

两组新增参数量相同，但不是严格等 FLOPs 或等有效容量对照：逐点组的注意力只看
自身，相应的注意力选择自由度自然退化。它主要用于区别“逐点容量增加”和“使用邻居”
的收益，不能据此排除所有结构差异。K=16、宽度64 是公开的工程起点，不是最优设置。

## 接收端链路和前缀边界

每一级先执行现有完整前缀恢复，再加残差：

`当前前缀符号 + 前级恢复 → 当前 ŷ → 新残差修正 → 本级输出`。

新支路输入仅为当前级已接收符号、相应接收掩码、当前恢复 y、SNR 条件和已交付 XYZ。
正确 y 仅作训练监督，不进入接收端。没有新参考信号，没有新位置预测，没有额外反馈链路。
clean 绕过信道模块，仍保持原教师路径。

q1 的邻域只能使用 q1 前缀和 q1 中间恢复；q2 不能借邻居读取 q3 后缀。
每一级仅在 `q >= 当前级` 的点中聚合，q0/padding 完全排除。较低级修正进入后续
恢复，因而高档监督可以更新前级新增支路，但原有网络参数保持冻结。

距离按 bbox 三轴跨度还原为世界尺度的等比例度量，不直接对逐轴归一化 XYZ 求距离。
邻域严格限制在原 Morton 局部块内部，不跨训练 batch 或块。相对位移进入可学习的
聚合，绝非直接平均属性；空间邻近仍可能跨越表面边界，因此必须检查细节是否被抹平。

## 训练、部署与诊断一致性

训练使用 `delivered_positions` 产生的 16bit XYZ，部署使用真实坐标流解出的 XYZ，
两端都从已知 bbox 元数据取得距离尺度。不允许训练时用浮点原始坐标偷偷替代可靠交付坐标。
receiver-only 解码不需要发送端语义网络或原 PLY。

含空间支路时，特征诊断先在完整原始 codec batch/局部块内恢复，再抽取固定32768点
进行8次噪声的误差统计。不能把随机抽出的点重新拼组去做空间去噪。
因此 `diagnostic-batch` 不再改变接收端分组，实际诊断显存取决于原 codec batch；
两组均采用这一诊断方式，噪声按组/试验固定配对。验证仍是相同视角、相同完整场景。

## 启动和输出

```bash
CUDA_VISIBLE_DEVICES=1 bash scripts/test_channel_spatial_truck.sh SOURCE_FULL_PREFIX_RUN NEW_OUT
```

可传完整前缀 suite 根目录或其中 `full_prefix10` 子目录。源目录只读，输出必须另建。
两组默认在同一张卡顺序运行，每500步评估/保存；只保存初始和最终的渲染图。
所有日志、诊断、对比图和结果统一放在 NEW_OUT 内。
中断后以相同输入/参数/输出追加 `--resume-suite`，恢复新增支路的 Adam、RNG 和进度。
常规旧训练命令不支持替代该专用恢复入口。

重点看 `comparison/summary.json` 的两组相对源模型增益与 `spatial_minus_pointwise_psnr_db`，
并同时核查：

1. q1/q2/q3/mixed 的噪声 NMSE、无噪声误差、Source PLY 和照片 PSNR/SSIM。
2. 空间组是否优于逐点容量对照，不能只看空间组比源模型好。
3. 噪声波动项、逐点均值误差、颜色误差和局部细节是否同时改善。
4. 初始化匹配、冻结校验和额外运行时间。单种子、单场景不是泛化证明。

如果只有逐点组与空间组一起改善，则额外逐点恢复容量可能更重要；若空间组进一步
改善，才支持邻域信息有增益。没有预设升档单调性或预设画质一定提升。
