# 完整接收前缀重读：独立结构对照

这是第三项改进的测试版，不替换原 progressive/suffix 基线，也不改上一项
无噪声 vs 10 dB 的对照。单独使用 `scripts/test_channel_prefix_truck.sh` 启动。

## 只改变接收端增强层能看到的信息

原路径：

- q1：由第一段接收符号恢复 y1。
- q2：第二段符号 + y1 → 修正量，累加得到 y2。
- q3：第三段符号 + y2 → 修正量，累加得到 y3。

测试路径：

- q1 完全保留。
- q2：前两段接收符号 + y1 → 修正量。
- q3：前三段接收符号 + y2 → 修正量。

低档看不到尚未收到的符号。q3 不能倒过来改变这次前向过程里的 q1/q2 读出。
高档 loss 仍可联合更新前层和共享编码器：保留原有梯度策略，不宣称升档质量必然
单调提升，也不保证续训中 q1 不变化。因此所有档位都需要评估。

## 保留起点和 Adam 的升级方式

新增输入通过一个独立线性投影进入原增强层：

`h = W_suffix * received_suffix + W_y * previous_y + W_history * received_earlier_prefix + bias + SNR_condition`。

这与将完整前缀一起交给同一个线性输入层等价，但保持原矩阵的形状、名称和对象
不变。新增 `W_history` 初始化为零，初始输出应与旧模型一致；新权重可以获得
梯度，不是永久关闭的门。

旧参数的 Adam 状态全部保留。新投影没有旧动量，从自己的第一个更新开始计数。
优化器参数顺序与新模型工厂保持一致，保证 checkpoint 重载后动量不对应错参数。
对照汇总会检查两组初始特征误差和画质是否匹配。

8/24/48 预算、隐藏宽度 192 下，新增参数为
`(2*8 + 2*24)*192 = 12288`，约为原信道参数的 0.42%。不增加网络深度，不增加
每点复符号 payload，也不传正确 y 或任何额外逐点参考。配置/模型标识元数据仍
按现有程序计费，因此不宣称包头逐字节相同或严格等参数量。

## 实验设置

从原 `truck_progressive_budget82448_gpu0_20261014_165028/progressive` 完成的
4000 步 checkpoint 同时分出：

- `suffix10`：原结构，10 dB，再训练 2000 步。
- `full_prefix10`：零权重升级，10 dB，再训练 2000 步。

两组在一张卡上顺序跑，默认保留源学习率 1e-4、语义模型冻结、48 维 y、原预算、
16bit XYZ、功率归一化和纯 y MSE。点批次和 mixed 掩码逐步相同，噪声随机流从
同一源状态开始。只做渲染评估，不做渲染更新。不要从 clean 教师重新初始化。

初始/最终做相同 32768 点、8 次噪声诊断；每 500 步保存数值，只有初始/最终
保存渲染图。输出包括两组日志、逐维 CSV、无噪声/10 dB 的 q1-q3 PSNR 曲线和
`comparison/summary.json` 中的 `full_prefix_minus_suffix_psnr_db`。

```bash
CUDA_VISIBLE_DEVICES=1 bash scripts/test_channel_prefix_truck.sh SOURCE_RUN NEW_OUT
```

中断后保持相同输出/参数，追加 `--resume-suite`。原 checkpoint 只读。
默认配置 `channel_prefix_mode=suffix` 不写入旧格式配置字典，旧 checkpoint 和
已有 inverse 实验计划保持兼容；full_prefix 仅由实验升级或显式配置启用。

## 看哪些结果

1. 初始恢复是否匹配；不匹配时不能当成干净的续训结构对照。
2. q2/q3 的无噪声特征误差与 10 dB 特征误差分别是否下降。
3. PSNR、SSIM、颜色偏差是否同时改善，不只看 MSE。
4. q1 是否因共享优化而退化，q3 相对 q2 的增量收益是否增大。
5. 单步耗时和诊断噪声方差是否增加。

若只有噪声条件改善，说明更完整的接收观测可能帮助纠错；若无噪声也改善，说明
原增强层的输入限制可能妨碍精确恢复。一个 checkpoint/训练种子的对照只提供机制
证据，不是普遍性证明；也不能将新增参数的影响完全排除。
