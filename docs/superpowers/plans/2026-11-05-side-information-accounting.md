# 侧信息统一计费实施计划

> 执行方式：使用 superpowers:executing-plans，在当前仓库逐项实现。

**Goal：**以数字基线实际文件协议计量 JSCC 的三路侧信息，并生成已有结果的统一账本。

**Architecture：**数字传输与账本共用文件长度计费函数。JSCC 的坐标、元数据、尺度分别作为文件封装，属性直接计复符号。评估增加独立的比较账本，旧训练成本与选模 RD 保留。

**Tech Stack：**Python 标准库、pytest；真实数字链路验证复用现有 Sionna CPU 测试。

**Spec：**本文定义本次改动范围与协议。

## 协议与范围

- 默认 5G LDPC k=4096、n=6144，16QAM，48 字节文件头，每信息块含 CRC32。
- 每文件成本为 ceil((bytes+48)/(k/8-4)) * n/log2(M)，三路分别取整。
- 空文件仍按真实文件头收费。原尺度流内部帧头保留，外层文件封装另计。
- 不重训、不重新选模、不改历史训练目标；共享模型预置。
- 数字基线保留实际传输成功率，JSCC 侧信息标注可靠交付假设，未模拟其误码。
