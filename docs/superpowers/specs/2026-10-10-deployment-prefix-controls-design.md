# 十次部署对齐、前缀保持与精简输出：受控实验设计

状态：用户已选择直接同时实现两项改进；实现与验证记录见同日 implementation 计划。

最新决定覆盖下文的早期分组建议：本轮只运行 C（十次部署对齐 + 固定前缀保持），
不自动拆成 A/B/C。中间验证不保存渲染图，初始与最终保留学习部署、q1、q3
及随机 mixed 的代表视角。所有指标、噪声试验和置乱对照保持完整。

## 1. 目标和边界

从已完成的多场景实验 `checkpoints/end_allocation` 出发，继续研究联合阶段的两个问题：

1. 单次训练采样与十次部署决策不一致。
2. 联合阶段只训练学习布局，固定 q1–q3 的恢复能力下降。

成功标准是相同实际通信成本下获得更好的测试画质，或相同画质下获得更低成本。不是追求更高删点率，也不是给各档位设置强制配额。

本轮不修改编解码器架构、可靠坐标交付、4/12/24 符号预算、10 dB AWGN、原 PLY 渲染 MSE 目标、训练场景名单和测试划分。暂不新增属性损失，不更换 q0 删除原则，不提高 beta，不开展新的独立边际收益反馈训练。

## 2. 实验分支

| 分支 | 分配采样与成本代理 | 联合阶段前缀保持 |
| --- | --- | --- |
| A | 十次部署对齐 | 关闭 |
| B | 原单次采样 | 开启 |
| C | 十次部署对齐 | 开启 |
| reference，可选 | 原单次采样 | 关闭 |

A/B/C 均从同一 `end_allocation` 编解码器和对应场景分配表初始化；每个训练场景进行 1,000 次联合更新。不是重新训练前两阶段，也不把新的分配表重置为高保留初始化。

原检查点只保存权重和分配表，未保存 Adam 状态。所有分支统一重新创建优化器，并显式记录 `branch initialization; not exact resume`。既有 final 结果仅作为历史参照；若需要排除优化器重置和随机序列变化的影响，使用可选 reference 分支。启动脚本默认不自动增加这第四组。

学习率沿用 1e-4；beta 沿用 0.01；每场景 64 blocks/batch、两视角/replay。验证间隔沿用每场景 500 次更新，首次和结束也验证。不得通过减少 B/C 的学习分配更新数量补偿额外前缀计算。

## 3. A/C：前向与部署使用相同规则

保留当前部署定义：抽十次 q0–q3；十次全部为 q0 才不传；否则选择正档位出现次数最多的档位。正档位计数并列时，依次使用已学习概率和随机数打破并列。

训练重新采样，不固定使用测试导出的一张档位表。目标是相同决策分布，不是每一步都复用同一张部署表。评估和发送仍使用固定种子，接收端不重新采样。

当前模型有“是否保留”和“保留后档位”两个分支。训练的十次层次采样应与当前四类别部署概率产生相同分布；公共的计数和并列处理函数保持一致。

### 3.1 反向路径

前向采用真实离散十次决策；反向仍为局部、有偏的 straight-through 代理，不宣称离散 argmax 或压缩字节可精确求导。

- 存在分支：硬值对应十次是否至少保留一次；软反向值使用十次软关闭概率的乘积补集。
- 不允许直接把十个 hard-ST 存在值做乘积后求导，因为多个硬保留样本可能造成零导数。
- 正档位分支：硬值对应正档位众数，软反向使用十次软正档位票数的归一化代理。
- q0 继续通过硬零门控的反事实 Gaussian 获得图像反馈，不恢复“每块最多四个 q0 候选”的上限。
- 反事实点不得进入实际编解码器的有效上下文；不让未发送点成为部署端不可获得的信息。
- replay 必须复现采样及并列决策；保存紧凑种子/状态，不把全场景十次噪声矩阵作为结果输出。

软投票代理的温度、稳定化方式和估计器名称都要记录。梯度有限、非零是机制正确性的检验，不代表代理已被证明无偏或优于旧版。

### 3.2 通信惩罚也对齐十次规则

若单次 q0 概率为 p0，十次部署的关闭概率是 p0^10。坐标代理成本使用 1−p0^10，而不是 1−p0。

正档位不能继续直接用单次类别概率计算 payload 期望，因为众数会改变部署后的类别分布。本轮四类别、十次抽样共有 286 个多项计数模式；按多项概率和与部署一致的众数/并列规则累计每个输出档位的概率，计算部署 payload 期望。完全相同的概率并列，随机并列选择的期望应保持对称。

按块计算并及时反向，不能为数百万点保留 N×286 的全场景计算图。概率为零或接近边界时避免 NaN/Inf；验证期望概率总和、p0^10、极端档位和 Monte Carlo 采样的一致性。学习概率优先打破计数并列的规则有分段边界，必须记录其求导限制。

压缩坐标的每保留点成本仍使用已测量的局部代理；档位压缩和非可分侧信息仍不宣称精确求导。完整实测包成本用于评估，并与训练代理分开命名。

代码审查发现当前 `AllocationCostMeter.normalizer` 是全部 q3 的属性与侧信息代理总成本/原始点数，不是固定 24。为避免本轮同时改变惩罚强度，A/B/C 沿用同一初始化和现有归一化规则，明确写入日志；不能在结果分析中悄悄改用除以 24。是否恢复固定 24 留作单独决策。

## 4. B/C：联合阶段保留固定前缀能力

每四次学习分配联合更新，额外执行一次固定前缀的整场景渲染，按 q1→q2→q3 循环。使用同一训练相机批次，不增加测试相机参与训练。

额外前缀渲染只更新编解码器，不更新分配表，不引入新的属性或位置辅助损失。前缀保持事件中的编解码器梯度为学习布局 MSE 与固定前缀 MSE 的等权平均；分配器仍获得原学习布局画质反馈和完整 beta 惩罚。不得把分配器梯度也减半，从而暗中改变其画质/成本取舍。

每次联合更新仍仅进行一次编解码器优化器 step 和一次当前场景分配器 step。replay 的多次反向不等于多次更新。额外前缀调用置于独立 RNG 保存/恢复范围，避免新增随机调用改变之后的分配采样序列。

每四次一次是初始工程频率，公开可调，不宣称最优。记录实际前缀次数、档位、两个 MSE、合并方式、前缀耗时和总耗时。B/C 的额外计算量须在结果中披露。

## 5. 精简输出，不精简评估

提供 `compact` 和 `full` 两种输出配置；新实验脚本默认 compact。只约束新结果生成，不删除已有 output，也不对旧目录执行清理。

### 5.1 保留内容

- 全部训练日志与逐场景/宏平均验证指标。
- 全测试视角、三次信道试验的 per-view 指标；全部固定档位与两类置乱对照，保持三种置乱种子。
- 原 PLY 与照片的 PSNR/SSIM/MSE、实际档位计数、期望与实际通信成本、前缀增益、耗时、协议假设和检查点身份。
- PNG 格式的学习曲线、档位分布、率失真、前缀增益图和对应小型数据表。
- latest、best_joint、final 匹配的编解码器与分配表检查点，留在服务器用于后续实验。当前支持的是权重/表初始化，不冒充带 Adam 状态的精确断点续训。

### 5.2 默认少存内容

- 中间验证只保存指标，不保存渲染图。
- 初始和最终测试保存四个固定代表性视角的 mask、全 q1、全 q3、随机 mixed 面板；相同视角跨布局、阶段保持一致。
- 置乱对照的所有指标照常计算，但默认不保存置乱渲染图；诊断开关可指定置乱布局生成图像。
- compact 不同时输出重复 PNG/PDF/SVG，不为每个验证时刻复制完整概率矩阵，不输出测试 packet、接收 PLY、逐点符号数组或大噪声矩阵。
- 档位变化率使用运行期上一张硬档位表或 latest 轻量表计算；减少概率矩阵落盘不能让变化率失效。
- 不重复复制初始化检查点；记录初始化路径、身份和文件校验即可。

图像限制只影响保存，不改变测试视角数、布局数、信道试验数、模型选择或随机数序列。必须保存代表性视角名称和图像保存策略。

### 5.3 下载包

全部结果位于一个运行根目录；结束时生成 `review.zip`，收集用于本地分析的小文件、代表性图像和曲线。

下载包不包含检查点、原始数据、重复概率数组和符号文件。保留必要训练配置、完成状态、指标、图像清单、检查点身份；列出排除内容并给出包大小。用户只需下载 review.zip，若要在本地做额外推理，再单独取对应检查点。

归档使用明确的文件白名单，包含 root 和各场景的必要记录，不用递归打包整个 output；不跟随符号链接或引入运行目录以外的文件。只有训练和评估成功完成后才发布完整下载包，异常退出不得伪造 complete 状态。

## 6. 受控验证和验收

本机 CPU 可验证逻辑、梯度、检查点和文件输出，不能替代服务器 CUDA 场景质量评估。

1. 硬决策测试：十次全 q0、正档位众数、并列概率/随机规则、原始行顺序和种子复现。
2. 梯度测试：多个保留抽样、全 q0、极端概率下存在与正档位梯度有限；replay/直接反向在相同样本上相符。
3. 期望成本测试：输出概率和为 1，关闭概率等于 p0^10，payload 期望与枚举/Monte Carlo 相符；块级计算与小规模整批计算一致。
4. 前缀保持测试：固定事件不改分配器梯度，学习更新数不减少，优化器只有一次 step，额外前缀调用不改变后续 RNG 状态。
5. 分支初始化测试：加载原 PLY 匹配表、codec identity/rates 一致；缺失或错配表立即报错，不静默重建。
6. 精简输出测试：compact/full 的所有指标和种子一致；图像数、概率数组、图表格式和归档白名单符合配置；旧输出不变。
7. 合成端到端测试：A/B/C 都完成一次可检查的短流程；不把合成渲染 PSNR 当真实质量改善证据。

服务器主要比较实际总成本—画质曲线、全 q1/q2/q3 能力、学习部署画质、全部置乱与仅正档位置乱增益、训练/部署差距及额外耗时。beta 相同也不保证总 loss 能解释全部变化；真实包成本与训练代理必须分别展示。

## 7. 后续问题和本轮不承诺内容

- 新代理改善部署一致性不等于已经解决档位梯度质量问题。
- 保住前缀能力不保证每个点或每个视角的 q3 都优于 q2；不增加硬单调约束。
- 首轮 A/B/C 使用一个训练种子，是机制探查；稳定结论仍需要额外训练种子。
- 若这些改动有效，再做固定删点集合、冻结编解码器的正档位边际反馈实验。
- 如果不运行 reference 分支，须保留优化器重置这一比较限制。
