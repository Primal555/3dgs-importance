# 固定 beta 的率失真分配模式

状态：用户于 2026-10-24 确认实现；已在当前仓库实现独立固定 beta 模式，保留预算模式。启动与结果说明见 `../../budgeted_allocation.md`。

## 目标与选定方式

用户希望通过固定通信惩罚强度，让分配器自行选择通信量，不预设总预算或档位占比。沿用已训练的 successive 编解码器，只学习所选场景的保留/条件正档位概率表。

已讨论两种方式：

- 预算约束：指定总成本上限，自动调整通信价格，在达标候选中选择画质最好的方案；旧实验保留。
- 固定 beta：固定画质与通信成本的交换权重，按率失真目标优化和选择候选；用户已选择此方向。

不混合两种控制机制，不以降低 beta 作为强制获得某种档位占比的手段。

## 损失、量纲和模型选择

训练目标：`L_proxy = D_train / D_ref + beta * C_proxy / C_ref`。

- `D_train` 仍为源 PLY 渲染图的多视角 RGB MSE。
- `D_ref` 固定为输入编解码器在全 q3、10 dB、校准视角上的初始平均 MSE，保留既有 1e-12 数值下限及原始值记录。
- `C_ref` 固定为同场景、同模型全 q3 的实测总复信道使用次数；它只用于归一化，没有达标含义。
- `beta` 通过必填参数显式提供，允许 0，拒绝负值及非有限值；全过程固定，不运行预算价格控制器。改变 beta 使用新输出目录。
- 训练中仍以 payload 精确计数和最近实测侧流构造局部成本代理，不宣称对压缩字节数精确求导。
- 校准候选评分：`RD_deploy = D_calibration / D_ref + beta * C_actual / C_ref`，使用固定 seed 的十次规则部署、真实侧流和实际档位成本。选择评分最小的 `best_rd`；同分时优先更低失真，再优先更低成本。
- 最终测试相机不参与选择。保存 initial / latest / best_rd 的真实成本、画质及评分。保留 latest，避免用单个被选中的端点掩盖后期波动。
- 不输出预算达标标签或 budget_unmet；不按概率期望成本选最终部署。

新归一化目标下，历史 beta=0.005 不代表相同惩罚强度。首轮系数由启动参数明确指定；后续不同 beta 实验共享同一输入模型、场景、相机划分及固定参考尺度，绘制实际部署率失真曲线。

文献依据：NTSCC 第三节式（17）支持重建失真与主要内容/数字侧信息总通信资源的加权权衡；FCGS 第 3.4 节式（8）、HAC 第 3.4 节式（9）支持渲染失真与归一化编码成本联合优化；RDO-Gaussian 第 3.2 节支持逐 Gaussian 资源选择。这里采用的全 q3 双参考归一化、镜像更新和多视角窗口为本项目工程设计，不作为上述论文的原有方法。固定参考下，本目标与 `D + beta * D_ref / C_ref * C` 等价。

## 保留的机制和实验范围

- q0/q1/q2/q3 = 0/8/24/48 复符号；可靠 16bit XYZ 与 binary16 块尺度不变，固定 10 dB。
- 所有编解码器及属性统计量冻结；本轮无联合微调。
- 默认单场景 2000 次更新，每次四视角累计反馈。单次硬采样学习、十次规则部署不变。
- 保留全部 q0 反事实反馈、真实混合邻域单点升降档候选、保留幅度信息的镜像更新、覆盖轮换与同一步缓存复用。
- 成本仍包括属性 payload、XYZ、完整元数据/档位表和尺度流。可靠侧流记录原有净 bit/use 假设及真实字节数，共享模型权重不计入本次场景交付。
- 每 25 步仅更新实际部署成本及局部侧流代理，不更改 beta；每 250 步校准；每 100 步保存。最初与最终端点保存代表图及档位着色图，相同端点去重。

## 实现边界与验收

建议在新分配器中增加显式固定 beta 模式并提供对应启动脚本，复用核函数和缓存，保持旧预算入口兼容。固定 beta 与预算参数互斥；日志、模型选择、报告、续训均按模式区分。

记录 source/photo PSNR、SSIM、LPIPS，实际 q0–q3 占比，真实总成本及拆分，代理/部署 RD 评分，固定 beta 和归一化基准，覆盖与耗时。单组输出训练轨迹；多 beta 结果以真实成本—画质比较，不能横向排名不同 beta 的总 loss。

精确续训保存 beta、参考尺度、概率表、覆盖/相机游标及 RNG，不接受改变 beta 后伪装精确续训。旧预算 checkpoint 保持原行为，不能静默转换目标。

定向测试覆盖：参数互斥及 beta=0、固定系数不漂移、成本梯度尺度、真实部署评分选 best_rd、代理下降但部署评分恶化、续训一致性、报告及旧预算模式兼容。验证运行范围与结果如实报告；CUDA 耗时留待服务器实测。不启动全仓历史训练回归，不改用户其他未提交文件。

## 实施验证记录

39 项定向和兼容测试通过，覆盖固定目标、入口、冻结权重、成本刷新、校准选模、报告、实际 Bash 启动和中断续训，以及旧预算/kernel/mirror/reuse 路径；Python 编译、Bash 语法和 diff 检查通过。独立只读审查未发现 Critical/Important 问题。尚未进行完整 CUDA 收敛、显存或速度测量。

独立审查留下两项非阻塞测试增强：直接损坏 checkpoint 的 D_ref/C_ref 后检查无输出改写；人为构造端到端候选，使画质排名与率失真排名相反。当前已有对应输入检查、参考尺度保存/续训验证，以及独立目标函数的反序/误导代理案例；上述更强的边界场景尚未加入生命周期回归测试。
