# 共同条件下的直接档位分配

依据 `truck_direct_diagnostic_gpu2_20261102_151138`，修正候选条件错位、高风险动作入选和整批拒绝。用户已批准本轮实现。

## 决策与预算

- 编解码器、收益网络、失真归一化和 beta 保持冻结；新入口从全 q2 开始，支持新入口精确续跑。
- 大范围初筛仍每窗口评价约5562点；初筛条件仅用于发现候选。
- 每10窗口最多512点，在相同4个分配优化视角、相同2组固定噪声下重新预测全部四档。预留四分之一名额均匀覆盖初筛排序的其他位置。
- 重评分后最多64点复用候选四档投影取得真实局部标签，再按实际单点收益选择动作。其余共同条件网络候选也可进入联合验收。单点排序使用既有边际成本近似；整批验收使用完整实际通信成本。
- 每块最多一个动作。真实复核通过的动作每批16个，优先独立验收；未逐点复核的网络动作按剩余预算分成互不重叠的根子批。两类动作不混在同一个根子批中。失败后拆分，每轮最多12次联合局部检查。每次通过后提交；后续检查包含此前已通过的全部变化。
- 联合局部渲染覆盖完整变化块、全部受影响 tile 和 SSIM halo，使用相同视角、噪声及 MSE+结构目标。每100窗口及最终进行完整渲染核对。

## 缓存与一致性

- 固定地图时缓存每个噪声条件的完整解码、基线捕获、可见性与空间统计；禁止保存全场景所有候选四档。
- 仅重评分候选缓存解码和投影；真实复核、失败拆分复用投影，不再次运行网络或编解码器。
- 地图改变后清空旧背景缓存和提案，下一窗口重建。每轮子批使用共同原始背景加累计已通过替换，确保重叠区域和非线性相互作用被实际计算。
- 从训练相机中选分配优化视角，明确记录身份；独立测试相机不参与提案及验收。
- 使用已有精确 tile 渲染器，不增加 CUDA 内核。

## 输出

仅保存初始和最终图、统一 q2/q3 指标、最新恢复 checkpoint、小型 review 包。日志记录分阶段时间、缓存命中、重评分/真实复核/联合检查次数、实际收益和拆分结果。checkpoints 不进入 review 包。

## 验证

使用真实小块编解码器验证两噪声缓存、真实标签与完整渲染、累计子批和 q0 恢复；用反例验证同条件重排序及失败批不会阻止独立有利批；验证预算上限、精确断点续跑和原入口回归。CUDA 一致性由服务器启动 preflight 验证。
