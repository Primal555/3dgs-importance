# 接收端块级定位 token 实验

在 Transformer 主干解码上增加一个只读定位分支，不替换原有 XYZ 预测，不传粗坐标。

## 结构与不变量

一个共享可学习 query，依次对主干浅/中/深三层接收特征进行 cross-attention，每层含 query LayerNorm 与残差 FFN。
最终线性头预测归一化坐标下的三维平移；该头权重和偏置从零开始。

`predicted_xyz[i] = base_xyz[i] + translation[block]`

- 对同一次前向的固定 base 输出，所有有效点加相同平移，因此相对坐标完全不变；属性也不变。
- 联合训练会改变主干和编码器，**不保证新旧训练模型的相对结构始终相同**。
- 新分支在原有模块初始化之后建立；同种子的新旧模型共享权重及初始输出完全一致。
- 初始第一步只有零初始化末层收到非零定位梯度；之后梯度进入注意力/query。这不是梯度故障。
- 只读取接收特征与有效点 mask；不读取源坐标、块中心或空间邻居，不增加符号预算。
- 查询是共享模型参数，不是每个数据块各自的可学习坐标；没有跨块信息交流。
- q0、padding、全空块安全屏蔽，单例/混合档位支持保留。

默认仍是 `decoder_localization=none`，新实验显式设置 `--decoder-localization token_translation`。
仅支持 `decoder_attention=transformer_trunk`；checkpoint 记录选项，旧模型哈希不变。
跨定位类型的训练初始化会拒绝，不能静默加载缺失权重。本次主实验全部随机初始化。

编码器、主干、多层 XYZ 头、logcov、`spatial_logcov_v1` 目标均不改动；没有新增位置辅助损失。
依然是 fixed q3、32 复符号、无噪声、固定 LR=2e-4、不裁剪，一阶段同时训练位置和其他属性。
原有共享全局 bbox/特征统计仍按原协议处理；没有额外的逐块坐标交付。

## 扩大本机测试

```bash
python scripts/compare_localization_large.py \
  --ply output/truck_mask_0005/point_cloud/iteration_30000/point_cloud.ply \
  --out output/localization_large_new \
  --steps 2000 --every 200 --save-every 500 \
  --blocks 64 --blocks-per-batch 4 --threads 4 --seeds 42 43 --workers 2
```

- 64 个 256 点块，共 16,384 点，按全场景 Morton 完整块索引等分区间中点选取，不按结果筛块。
- 每四块最后一块留出：48 块拟合、16 块留出。
- 对照是 **当前 Transformer 主干** 的 none 与 token_translation，不是更早的窗口网络。
- 两种子 × 两结构 × 2000 步，共 8000 次参数更新；每步四块，同种子使用相同采样与监督方向。
- 相比上次 8 块/300 步/每步2块，数据块数量8倍、每个模型处理的点样本总次数约13.3倍。
- 所有目标与优化超参数一致，零初始化保证共同起点；CPU 并行独立种子，不合并其梯度。
- full-PLY 归一化统计共享，留出块不参与梯度；是同场景检查，不是跨场景泛化或严格独立测试集。
- 本机没有 CUDA，这些是位置与形状指标，不能当作渲染 PSNR。

输出都在一个实验目录内：

- `seed42/`、`seed43/`：两种子各自模型、checkpoint 和原始日志。
- `loss.jsonl`：每步目标、梯度范数及各参数组（含 block_localization）梯度。
- `validation.jsonl` / `blocks.jsonl`：固定拟合/留出总体及每块误差；含完整位置、共同偏移、相对误差、形状和预测点云展开比例。
- `without_translation_*`：同一已训练模型仅撤销平移分支，不是使用真实中心校正，也不是重训后的消融。
- 根目录 `comparison.json` 和曲线：最后三个固定检查点平均，不挑最好一次。

`spread_ratio` 用于识别预测点云塌缩/膨胀；相对位置误差变小本身不保证细节正确。
平移分支开关前后的相对误差应基本一致；若不一致，应检查实现而不是宣称收益。
`diagnose_position_path.py` 也提供完整解码与 `without_translation` 两路径分解。

## 实验边界

这是受 FLARE/VGGT 的整体几何信息读取思路启发的接收端迁移设计，不是论文复现。
共同位置偏差不意味着所有误差都是平移；该分支不能修复块内旋转、尺度或非刚性排列错误。
新增定位头不能凭空恢复 payload 未编码的信息，端到端梯度仍需让编码器保留位置信息。

默认参数量从 1,445,787 增至 1,670,718（增加 224,931，约 15.6%）。
定位查询只有一个 token，其 cross-attention 对块长度为线性规模；主干的块内自注意力仍为平方规模。

## 2026-09-21 本机完成结果

实验目录：`output/localization_large_paired_20260921/`。四个训练均完成 2000 步，两种子并行，约34分钟。
以下取1600、1800、2000步的 MSE 平均后开方；单位为原场景坐标单位，**不是 PSNR**。

| 指标（越低越好） | seed42 原主干 | seed42 加定位 token | seed43 原主干 | seed43 加定位 token |
|---|---:|---:|---:|---:|
| 拟合 XYZ RMSE | 1.6325 | 1.9002 | 1.6696 | 1.9450 |
| 留出 XYZ RMSE | 6.1353 | 6.7053 | 6.1973 | 6.7723 |
| 留出共同偏移 RMSE | 6.0576 | 6.6432 | 6.1171 | 6.7086 |
| 留出相对位置 RMSE | 0.9735 | 0.9109 | 0.9942 | 0.9265 |
| 留出 logcov shape 项 | 0.2212 | 0.2397 | 0.2809 | 0.2477 |
| 留出总目标 | 1.4253 | 1.5784 | 1.4144 | 1.5958 |
| 最后500步梯度范数中位数 | 82.71 | 190.26 | 85.32 | 191.91 |

结论：**保留为可选实验，不替换默认主干，不建议据此开展服务器长训练。**

- 留出相对 RMSE 下降6.4% / 6.8%，但整体 RMSE 上升9.3% / 9.3%，拟合 RMSE 上升16.4% / 16.5%。没有同时保住局部改善并提升整体定位。
- 逐块检查也不支持稳定收益：48个拟合块仅9 / 12个改善；16个留出块仅3 / 5个改善。这些块不是独立场景，不能据此作统计显著性结论。
- 留出点云展开比例从2.70 / 2.66降到2.42 / 2.31，仍明显大于1。相对误差改善不等于局部结构准确。
- 新模型去掉其已共同训练的平移分支后，留出 XYZ RMSE 为15.91 / 21.97；加回来为6.71 / 6.77。但这只能证明两个分支共同工作，不能证明它优于重新训练的旧主干。
- 新增平移的世界坐标 RMS 已达12.29 / 19.04，提示它不是小幅修正。`base + translation` 存在分解不唯一：base整体加一个偏移、translation减去同一偏移，最终坐标不变。大分支量与较小最终误差符合相互补偿的可能性，但仅凭这些统计不能断言这是唯一根因。
- 全程不裁剪，未出现非有限损失/梯度；新模型梯度中位数约为旧版2.3倍，**没有缓解大梯度问题**。梯度变大不自动等于数值发散。

下一步更有针对性的候选是明确区分“块中心”和“零均值局部偏移”，消除两条位置分支共同承担平移的自由度，而不是继续堆注意力层或加训练步数。
中心仍须从接收符号学习，不引入源中心交付；这是后续待验证设计，**本次没有实施**。
这些结果是同场景有限块的 CPU 重建对照，不能代替全场景 CUDA 渲染评估，也不能断言此结构在所有数据上无效。

验证：完整回归225项（221通过、4跳过）；补充初始共享梯度严格一致性断言后，定位模块10项测试再次通过；Bash语法和 `git diff --check` 通过。
